# 03 · UI / 视觉改进方案

## 0. 现状诊断（基于交接文档 + 截图反馈）

1. 首页入口不聚焦：两个功能像并列的工具，没有「主打玩法」的层级；评分作为宣发核心却没有视觉中心。
2. 现场评理流程「录两段→等→出报告」，没有回合感、没有仪式感，等待全靠转圈。
3. 报告页信息密度高但**没有一张能直接发朋友圈/小红书的图**——评分系统的传播价值没有兑现。
4. 「男方/女方」写死在 UI 和数据模型里，既有映射 bug 风险（第一个 speaker=男方），也排除了其他关系场景。
5. 缺统一 Design Tokens，颜色字号散落各 View，加模式必然越写越乱。

## 1. 首页（Home）

```text
┌──────────────────────────┐
│  冷静报告                 │
│                          │
│      ╭────────╮          │   ← Hero：上一场沟通总分的大圆环（ScoreRing）
│      │   72   │          │      没有历史时显示品牌态文案「今天也别吵输了逻辑」
│      ╰────────╯          │
│   A 44% ▕▏▏▏▏ 56% B     │   ← 责任占比条，直接复用报告组件
│                          │
│ ┌──────────────────────┐ │
│ │ 🎙 现场评理  主打 >   │ │   ← 大卡片，副标题「快速 / 回合制」
│ └──────────────────────┘ │
│ ┌──────────────────────┐ │
│ │ 📼 事后复盘        > │ │   ← 次卡片，导入录音
│ └──────────────────────┘ │

```

- 「奇葩说模式」不做首页第三入口，收进现场评理的模式选择页，首页保持两选一的决策简单度。

## 2. 模式选择页（LiveDebateModePicker）

- 卡片式两个模式：**快速评理**（各说 1 分钟 / 约 3 分钟出结果）、**回合制**（前情→开篇→反驳→总结 / 约 10 分钟）。
- 每张卡标注时长预期和成本档位（¥ / ¥¥，对应 02 文档的模式成本），连续录音显示「即将上线」占位。
- 进入前的配置面板：双方称呼（默认「男方/女方」，可改成任意二人）、可选议题输入框（「这次吵的是什么？」）、文风开关（毒舌 / 温和）。

## 3. 回合录音页（DebateTurnRecorderView）——体验核心

```text
┌──────────────────────────┐
│ 前情 ● 开篇 ● 反驳 ○ 总结 ○ │  ← 回合进度条（PhaseChip），当前阶段高亮
│                          │
│      现在发言：小张        │  ← 当前发言人，用参与者色（A=青 B=橙）整页染色
│                          │
│        ╭──────╮          │
│        │ 0:42 │          │  ← 大倒计时环，占屏 40%；最后 10 秒变红 + 每秒触觉
│        ╰──────╯          │
│    「反驳对方刚才的说法」   │  ← 当前 phase 的一句话引导词
│                          │
│   [ ⏸ 说完了，交给对方 ]   │  ← 唯一大按钮；90s 自动截断
│                          │
│ ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔ │
│ 上一回合 AI 小结：小李抓住了 │  ← 对方录音时，展示上一回合 TurnDigest
│ 「说好的分工」这个点…       │     的 compactSummary，等待时间变成内容
└──────────────────────────┘
```

关键决策：

- **参与者色用青/橙，不用粉/蓝**——避开性别刻板印象，也适配任意二人关系；色值进 Design Tokens。
- 交接手机的仪式感：回合切换时全屏翻转动画 +「请把手机交给 {对方称呼}」过场页，这是线下双人玩法的必要引导。
- 触觉规范：开始录音（轻）、剩 10s（每秒轻点）、截断（重）、回合小结到达（成功震动）。

## 4. 处理页（DebateProcessingView）

转圈改为分阶段清单，阶段来自真实 pipeline：

```text
✅ 转写完成（8/8 回合）
✅ 逐回合分析（8/8）
◐ 评委正在合议…
```

配轮换趣味文案（「正在检查谁偷换了概念…」「正在寻找本场金句…」）。由于 rounds 模式逐回合已经分析完，finalize 实际只剩一次调用，**这一页通常只有几秒**——这也是回合制架构送的免费体验优化。

## 5. 判决页（DebateResultView）——可截图卡片组

横滑卡片 deck（`TabView(.page)`），每张卡 = 一个传播点，右上角分享按钮用 `ImageRenderer` 出 9:16 长图（含 App 名 + 下载引导 + 固定免责声明 footer）：

1. **总评卡**：沟通总分大圆环 + 责任占比条 + 一句话终评
2. **核心矛盾卡**：「这场架真正在吵的是…」
3. **A 最佳论点卡** / **B 最佳论点卡**（参与者色底）
4. **本场 MVP 卡**：谁更抓住问题 + 理由
5. **金句卡**：评委金句 + 双方原话摘录（EvidenceQuote）
6. **责任雷达卡**：六维雷达（争点清晰度/证据密度/倾听/情绪热度/逻辑漏洞/修复空间）
7. **修复行动卡**：「最需要补的一句话」+ 和解动作清单

卡片下方固定小字免责声明（不可截掉，直接渲染进分享图）：

> 沟通责任估计，不代表事实裁决 · 评分用于复盘和娱乐

页尾附：完整逐句文字稿（折叠）、本场成本「¥23」（costMeter，透明化顺便当传播点）。

## 6. Design Tokens（Design/Tokens.swift）

```swift
enum DS {
    enum Color {
        static let participantA = ...   // 青 teal
        static let participantB = ...   // 橙 orange
        static let scoreGood/scoreMid/scoreBad = ...
    }
    enum Radius { static let card: CGFloat = 20 }
    enum Spacing { /* 4/8/12/16/24 网格 */ }
}
```

验收线：深色模式完整适配；Dynamic Type 到 XL 不破版；所有新 View 必须只从 Tokens 取色。
