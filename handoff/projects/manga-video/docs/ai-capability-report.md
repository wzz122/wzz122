# AI 能力边界报告：图解模板试作

试作片：`out/pilot-explainer.mp4`（79 秒，1920×1080，30fps）＋ `out/pilot-explainer.srt`
内容：故乡税第三段「年收 500 万到底能省多少」
日期：2026-10-27

## 先说结论

- **图解这一块，AI 写代码就能直接做到能上线的水平。** 9 张图解、字幕、效果音、口型、时间对齐全部自动生成，没有用任何生成图片。改一句台词后重新出片，只要 1 秒重算时间轴、50 秒渲染。
- **最弱的是声音和人物形象。** 这次用的是 Mac 自带的免费女声，把音调压低假装男老师，听得出是机器声。老师和芝士的形象是代码画的简笔占位，能看，但不够「像个频道」。
- **人必须把关的是内容本身**：数字对不对、规则有没有过时、哪句话该配什么图。这一点两种模板都一样，AI 替代不了。

## 1. 完全由代码自动生成、可以直接上线的部分

| 部分 | 怎么做的 | 质量 |
|---|---|---|
| 11 种图解组件（标题卡、滚动数字、要点、算式、对比、表格、横条图、时间轴、道具网格、注意框、芝士插话） | React + SVG 代码绘制，分镜里只填数据 | ✅ 可上线。数字绝对准确，不会出现生图常见的错字、乱码 |
| 画面跟配音对齐 | 分镜里写「念到哪个词时出现」，程序按配音的真实时长算到帧 | ✅ 可上线。例：念到「2,000」时算式第二项弹出，念到「八倍多」时盖红章 |
| 大字幕 | 自动按标点切成一屏一句；数字、金额、术语自动黄字放大；`**双星号**` 手动加重点 | ✅ 可上线 |
| .srt 字幕文件 | 和画面字幕同一份数据导出 | ✅ 可上线 |
| 效果音 | 用程序现场合成（弹出、滚动滴答、叮、嗖、警告音），按组件步骤自动挂上 | 🟡 能用，偏「电子音」。换成真实音效只需把同名文件放进 `public/sfx/` |
| 混音和音量 | 配音 + 效果音自动混好，统一到 −15 LUFS（实测 −15.1） | ✅ 可上线 |
| 口型、眨眼、表情切换 | 按配音音量逐帧算张嘴大小；眨眼按固定节奏；说到重点时老师自动抬手 | ✅ 逻辑可上线；好不好看取决于立绘 |
| 发音检查 | 配完音后用本机语音识别听写一遍，和台词对照 | ✅ 这次抓到了 2 处读错（见下文），修好后全部通过 |

**这次自动检查抓到的问题**：Mac 语音念「捐款减去 2,000，」时多念了几个零（听写出来是「200000」），「花 2,000」也读成了一长串数字，「One-stop」读得含糊。在发音词典 `config/lexicon.json` 里加了「2,000 → 两千」「One-stop 特例 → 万思多普特例」，重配后听写结果和台词一致。**发音词典这一步省不掉**：数字后面紧跟逗号、中日英混排的词，机器配音很容易读错。

## 2. 需要生图 AI 的部分，以及容易出的问题

这次**没有生成任何图片**。所有人物和道具都是代码画的占位，以后要换成生成图。需要的图和提示词写在 `docs/asset-prompts-explainer.md`。

| 素材 | 数量 | 生图容易出的问题 |
|---|---|---|
| 牛丼老师半身像 | 5 个表情 × 张嘴/闭嘴（再加闭眼）= 10–15 张 | **角色前后不一致**：眼镜形状、发型、领带颜色在不同表情之间会变。**张嘴和闭嘴必须是同一张图只改嘴**，直接各生成一张，切换时脸会跳。办法：先定一张标准图，其余都在它上面局部重绘 |
| 芝士小头像 | 2–3 张 | 和漫画版共用。漫画版的形象定下来后直接拿来用 |
| 道具图（大米、和牛、卫生纸） | 每期 3–6 张 | **图里的文字**：米袋、纸箱上很容易画出乱码字，要人工看，有字的重新生成 |
| いらすとや风格 | — | 生图模型容易画得过于精致或带阴影，不够「平」。提示词要反复强调「粗轮廓线、平涂、无阴影」 |

和漫画模板比，图解模板对生图的依赖小得多：**一套老师立绘可以每期重复用**，每期只多几张道具图。就算道具图没有，用代码画的带字占位块也说得过去。

## 3. 仍然需要人工判断或手工处理的部分

1. **事实核对**：24 万、5.7 万、4,600、三成这些数字是按「2026 年规则、年收 500 万、单身」写的。规则每年都可能变，上线前要人对照官方模拟器核一遍。代码只保证「写什么就画什么」，不会帮你发现数字本身错了。
2. **每段选哪种图解**：哪段用滚动数字、哪段用表格，现在是写分镜时人定的。AI 可以先出一版，但「这里用表格最清楚」这种判断，还需要人看一眼。
3. **配音音色**：免费的 Mac 语音没有中年男声，只能用女声压低音调，听感一般。要上线，建议换真人配音或 MiniMax 这类付费配音（漫画版已经接好了 MiniMax，填 Key 就能用）。**花钱与否由你决定**。
4. **最终观感**：节奏是否太快、字幕会不会挡图，需要人看完整片子。这次我按截图检查过，修了 4 处排版（算式超出卡片、红章盖住数字、对比卡文字折行、芝士气泡挡字）。
5. **角色立绘的筛选**：生图出来以后挑哪张、哪张不像，只能人来定。

## 4. 和漫画模板对比：每期的成本和自动化程度

| | 图解模板（这次） | 漫画对谈模板 |
|---|---|---|
| 画面主体 | 信息图，代码画 | 人物插画、场景，靠生图 |
| 每期新增图片 | 0–6 张道具图（没有也能出片） | 每个场景、每个新表情、新道具都要图，数量多得多 |
| 角色一致性风险 | 低：只有右下一个老师，立绘每期复用 | 高：多个角色同框、动作多，最容易「换脸」 |
| 数字准确性 | 高：代码画，不会错字 | 生图里出现的数字、文字容易出错，要避开或后期盖字 |
| 每期人工时间（估计） | 写稿和分镜 1–2 小时 + 核数字 + 看片 20 分钟 | 同样的写稿时间 + 挑图修图，大约多 1–3 小时 |
| 自动化程度（估计） | 约 85%：只有写稿、核实、看片需要人 | 约 60%：素材这一环需要人挑 |
| 出片速度 | 改一句到出片约 1 分钟 | 取决于要不要重新生图 |
| 风格辨识度 | 偏「理财课」，干净但容易和别的频道撞 | 更有个性、更像「自己的频道」 |

**建议**：平时用图解模板，开头放 15–30 秒的漫画小剧场把问题抛出来。这样每期要生的图只集中在片头几格，成本可控，频道也有自己的味道。

## 5. 下一步改进建议（按优先级）

1. **定老师立绘**：按 `asset-prompts-explainer.md` 先生成一张标准图，满意后再做其他表情。放进 `assets/characters/gyudon/` 就会自动替换占位，不用改代码。
2. **配音换成真人声或 MiniMax**：这一项对观感提升最大。两个模板现在用同一个配音模块，在 `.env` 里填好 MiniMax Key、在 `config/characters.json` 里填好音色，两个模板会一起换掉。
3. **AI 自动写分镜**：现在分镜（哪句配哪个组件、念到哪个词时弹出）是我手写的。下一步可以写成「给一篇文稿 → 自动出 storyboard.json 初稿」，人只改不满意的地方。
4. **换真实效果音和轻背景音乐**：现在的效果音是程序合成的，偏单薄。
5. **（已完成）和漫画版合并成一个预览入口**：`npm run studio` 里能同时看到两个模板。
6. **发音检查固定成一个命令**：这次是手动跑的本机语音识别，可以加成 `npm run check:explainer`，每次出片前自动跑。
