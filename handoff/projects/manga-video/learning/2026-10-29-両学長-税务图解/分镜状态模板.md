# 分镜状态模板（税务图解）

先分清楚：**「已接入」= 现在的 `build-episode.mjs` / `Scene.tsx` 会读、会校验；「仅规范」= 写在 `states.md` 给人看、或用现有对象拼，引擎不认识这个字段。**

可运行的完整例子：`episodes/furusato-v3-trial-new/scenes.mjs`（18 个状态，68 秒）。

## 1. 先在 states.md 写理解链（仅规范，人写人看）

每段先写这张表，再写代码。一行一个状态。

| 字段 | 写什么 | 例子（试作） |
|---|---|---|
| question_id | 这段回答开场哪个疑问（结尾行动要对应回来） | `how-much-tax` |
| 状态 id | 短英文 | `taxable` |
| 触发 | 第几句哪个词 | `9:还剩` |
| 观众要看懂什么 | 一句话 | 剩下的 238 万才是要交税的部分 |
| 保留 | 上一步留在画面上的对象 | income、d1–d3、premise |
| 只新增/改变 | 这一步唯一的变化 | income 的标签改成「238 万 要交税的部分」 |
| 视线 | 一个对象 | income |
| 最短停留 | 秒（初始参数，不是参考片测量值） | 3 |
| 为什么不换图 | 转换理由 | 同一根长条，切完剩下的就是答案 |
| 事实 | facts.md 编号 | F3 |
| 谁说话/谁在画面 | 两人全程在画面上（2026-10-29 用户定）；这里只写老师指什么 | 老师不抬手 |
| 音效 | 只给理解事件 | 叮-落定 |

经验值（试作参数）：一段 5–6 个状态是常态，推导链可以更多（试作 12 句 18 个状态）；简单句可以没有新状态。一般对象出现 0.3–0.5 秒，焦点移动 0.4–0.7 秒，结果稳定 1.5–3 秒。

## 2. scenes.mjs 里的 states（已接入）

```js
export default {
  tax24flow: {
    sfx: 'explicit',                 // 只响写明的音效（也可在 visuals.json 整期写 "sfxPolicy": "explicit"）
    states: [
      { id: 'goal', cue: '5', why: '先抛问题：24 万从哪来', focus: 'goal', hold: 1.2 },
      { id: 'taxable', cue: '9:还剩', why: '剩下的 238 万才是要交税的部分', focus: 'income', hold: 3, sfx: '叮-落定' },
      { id: 'notall', cue: '14:一部分', why: '只留能挪的那一截并指向它', focus: 'limit', hold: 3, point: 'limit' },
      // …
    ],
    objects: [
      { id: 'income', kind: 'bar', color: 'blue', role: 'neutral', label: '年收 500 万', h: 100, keys: [
        ['@whole', { x: 330, y: 330, w: 1100 }],     // 用状态触发
        ['6:能扣', { w: 783, dur: 20, label: '还剩 356 万' }],   // 状态内部的小动作照样写触发词
        ['@taxable', { label: '238 万 要交税的部分', pulse: true }],
        ['@zoom', { o: 0, dur: 12 }],
      ] },
      { id: 'limit', kind: 'bar', color: 'orange', role: 'paid', label: '上限', keys: [['@notall', { x: 330, y: 400, w: 261, sfx: 'pop' }]] },
    ],
  },
};
```

### 状态字段

| 字段 | 必填 | 引擎怎么用 | 校验 |
|---|---|---|---|
| `id` | 是 | 对象关键帧可写 `'@id'`、`'@id+0.3'`、`'@id-0.2'` | 引用不存在的状态 → 构建报错 |
| `cue` | 是 | 触发点，写法同旧的（`'7'`、`'7:词'`、`'7:end'`、`'7:词+0.3'`） | 状态时间倒序 → 构建报错 |
| `why` | 建议 | 写进审片页 | 缺 → 自检 WARN |
| `focus` | 建议 | 审片页、自检稳定时间 | 对象不存在 → 构建报错；到下一状态还没出现或已退场 → 自检 FAIL |
| `hold` | 建议 | 自检：焦点动完后到下一次被改动/退场/视线移走的秒数 ≥ hold | 不足 → 自检 WARN |
| `point` | 否 | 老师 `pointLeft` 手势 + 该对象橙色指示框（老师本来就在画面上） | 对象不存在 → 构建报错 |
| `teacher` / `cheese` | 不写 | 老师和芝士从头到尾都在画面上，不能离场（用户 2026-10-29 定） | 写 `'out'` → 构建报错；时间轴里有离场 → 自检 FAIL |
| `sfx` | 否 | 状态时刻的音效（音效库文件名，`pop` 会轮换 pop-1/2/3） | 0.15 秒内叠响 → 自检 WARN |

只要一个场景里有状态写了 `teacher` / `cheese` / `point`，这个场景的每个状态都会重置老师手势（没写 point 就放下手）。

### 对象新增字段

| 字段 | 用于 | 说明 |
|---|---|---|
| `role` | 所有对象 | `paid`（橙，付出去的钱）/ `credit`（绿，以后抵扣）/ `self`（黄，自己负担）/ `neutral`。颜色不符 → 自检 FAIL |
| `dash` | `box` | 虚线框（表示「误会的范围」「假设」） |
| `fill` | `box` / `rule` | `box` 的底色（`'transparent'` = 空框）；`rule` 的线色 |

### 你给的草案字段怎么对应

| 草案 | 实际 |
|---|---|
| `scene_id`、`learning_goal` | 场景名 + 第一个状态的 `why` |
| `question_id`、`fact_refs` | 仅规范：写在 states.md（引擎不需要） |
| `objects[].semantic_role` | 已接入：`role` |
| `states[].keep` / `change` | **没有做成字段**。原因：引擎里对象一旦出现就一直在，直到某个关键帧把它 `o: 0`；「保留」是默认行为，「改变」就是对象在 `'@状态'` 上的关键帧。另设 keep/change 会和关键帧写两遍、互相打架。自检用「焦点对象是否在画面上」代替 keep 的检查 |
| `focus`、`min_read_hold_sec`、`transition_reason` | 已接入：`focus`、`hold`、`why` |
| `cue.line/word/manual_offset_sec` | 已接入：`cue` 字符串 + `cue-fixes.json`（人工时间，按「s段_l句:词」记） |
| `teacher.visible/target_id` | 已接入：`teacher`、`point` |
| `sfx_event` | 已接入：状态或关键帧上的 `sfx` |
| `review_frames` | 已接入：`pipeline/review-states.mjs` 自动截开始前 / 变化中（+8 帧）/ 结束前 |

## 4. 常用配方

### 4.1 分步计算（已在试作里验证）
1. 先把整体画成一根长条（同一个对象）。台词说「要先扣掉几块不用交税的钱」时，在长条下方画一个空的灰色虚线框，左边写「不用交税的钱 →」；后面切下来的几块就落进这个框（试作状态 `notax`，2026-10-29 用户要求填上推导开头的空白）。讲公式前框和字一起退场。
2. 每扣一项：灰色一截先**盖在长条上**表示「就是这一截」，再落下来，长条同时缩短、标签改成「还剩 …」。
3. 讲到公式：已讲的扣除缩小排到一边（保留），公式卡出现：第一行结构（`所得割 ＝ 要交税的部分 × 10% − 调整扣除`），第二行代入（`＝ 238 万 × 10% − 2,500`），说到结果时加第三行（`≈ 23 万 5 千`）。
4. 结果所在的那一小段要放大成下一步的主角时，用同一个 id 改 `x/y/w`，其余对象退场。
5. 名词第一次出现时把中文意思和日文原名写在那一块旁边（`① 上班族固定扣除 / 給与所得控除`）；估算条件写在估算的那一块旁边（`② 社保 / 按收入 15% 估算`）。
6. 版面（2026-10-29 按用户意见调过）：标题 y 100，前提卡 40px、y 198；推导部分放在前提卡和字幕之间偏中间——长条中心 y 390，扣除落到 y 530，公式卡 y 605 / 825。不要都挤在上半部。
7. 一个东西换位置时，如果路线会从别的对象上穿过去，就先淡出、换位置再淡入（`[['@s-0.4', { o: 0, dur: 10 }], ['@s', { y: 310, dur: 1 }], ['@s+0.05', { o: 1, dur: 10 }]]`），同位置要退场的东西提前退场。

### 4.2 异议澄清（已在试作里验证）
芝士提问状态：把误会画出来（虚线框套住误会的范围 + 一行问句）。老师回答状态：说「不能」时框退场、问句换成「✗ …」，正确范围出现的同一刻 `point` 指向它。两个人物全程在画面上，不用出入场。

### 4.3 前后/内外对照（已在试作里验证）
固定基准不动（24 万长条和上限线），只改变一个变量：上限以内的橙色捐款下面接一段**同宽**绿色「明年扣回」，超出的黄色下面不接。颜色按语义：付出橙、抵扣绿、自付黄。

### 4.4 比较聚焦（仅规范，未渲染验证）
参考 V5 02:05–03:55。状态：
- `overview`：`doc` 列出全部比较维度，`hl: [当前行]`；身份色写在两列标题（不用橙/绿/黄）。
- `row`：`doc` 缩小移到一侧或淡出（`o: 0.25`），当前维度用两张 `card` 左右对照：先 A 事实、再 B 事实（两个关键帧），判断/评价另起一个不同样式的 `pill`，不和事实混在一张卡里。
- `exception`：例外大到会改变判断时，其他对象 `o: 0`，例外单独成主画面（不写成脚注）。
- `return`：`doc` 回到中间，`hl` 换到下一行。不必每行都回（V5 第 2 行就没回），切换话题或观众可能迷路时回。

### 4.5 列表焦点（仅规范）
参考 V4 08:20–10:50。当前项大字居中；讲完的项缩小（`s: 0.6`）移到下方列表保留；原因相同的几项合成一组，用一个状态讲完。

### 4.6 原件解释（引擎已有，规范补充）
`image` 对象：`cx/cy/z` 推近到要读的那一块，`marks` + `mk` 逐个亮框；中文解释用箭头指到对应框。出处和适用年份写进主体（卡片标题或旁白），**不放角落小字**。

### 4.7 行动闭环（仅规范）
开场在 states.md 记 `question_id`；结尾状态复用本章已出现过的对象（不引入新符号），给一个具体下一步。

### 4.8 简化画法 → 跟着台词拆开（仅规范，2026-10-29 用户定）
为了先讲清楚，可以先简化（例：把 5.7 万上限画成 24 万住民税长条上的一截）。规则：
- 简化处的标签写清楚是什么：「这个人的捐款上限：约 5.7 万」，不写成「住民税少交」。
- 台词讲到构成时，在**同一个对象**上拆开，不另画：上限那一截 → 左边一小段黄色「自付 2,000」＋ 其余绿色「明年扣回 5.5 万」（第 26–28 句）→ 绿色再分三块：所得税约 2,800、住民税基本分约 5,500、住民税特例分约 4.7 万（第 29–32 句）→ 两条路线：One-stop 三块都从住民税扣；确定申告约 2,800 走所得税退款、约 5.2 万从住民税扣（第 34–37 句）。2,000 只占 9px，拆的时候先把这一截放大再分。
- 台词留作答案的数字（芝士问「自己要掏多少？」→「2,000 日元」）不提前上屏。
- 写 states.md 时，对每个简化记一行「在哪一句拆开」；核对上屏数字时同时看后面几十句台词。

## 5. 每个状态的验收截图点
`node pipeline/review-states.mjs episodes/<期名> <输出目录> [--compare episodes/<旧版>]` 自动截：
- 开始前：状态时刻 −2 帧（上一状态的样子）
- 变化中：+8 帧（约 0.27 秒，看过渡有没有穿插、遮挡）
- 结束：下一状态 −3 帧（最后一个状态截在退场淡出之前）

再用 `ffmpeg -ss <秒> -t 1.2 -i 样片.mp4 -vf fps=6` 抽关键转换的连续帧，看动作过程。
