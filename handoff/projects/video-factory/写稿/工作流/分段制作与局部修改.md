# 分段制作与局部修改

用户要求（2026-10-02）：20分钟左右的样片可能反复修改许多小模块，制作时必须保留足够修改空间，避免改一处就重渲整片。

## 当前状态

已查当前源码：`engine/run.mjs`调用一次`renderVideo`渲染完整时长；`engine/render.mjs`从第0帧循环到全片末帧。`engine/media.mjs`有部分素材处理缓存，但画面与配音的分段增量缓存尚未实现。刘欢67.4秒样片保留了人物PNG、源码、分镜及帧缓存，目前也尚未实现按镜头自动判断变更并局部重渲。

下述是后续长片必须落实的制作要求，不能将规范已保存当成引擎已验收。正式制作20分钟片前，先跑通最小局部修改验收。

## 制作结构

1. 按章节组织；章节内按完整表达划分独立镜头，通常10–30秒，依内容调整。每个镜头使用稳定编号，例如C03-S02；插入或移动镜头时原编号保留。
2. 每个镜头保存源文件、可编辑参数、引用素材、局部时间与独立视频。位置、大小、文字、数字、颜色和动画节奏可分别调整。人物、道具与背景尽量保留独立素材，人物沿用图二风格与两遍视觉检查。
3. 图解画面、可编辑文字、字幕、旁白、新闻原声、音乐、音效分别保存。字幕保留SRT/可编辑字幕轨；旁白按自然段落组织，并保留原录音及局部对齐数据。避免只留下烧成一体的长MP4。
4. 镜头内部使用局部时钟；全片顺序和累计时间由装配清单计算，以整数帧为准。加长中间一段时，后续镜头移动位置，无须仅因全片时间变化而重新生成其画面。
5. 转场单独保存配置；根据效果保留片头片尾余量，必要时重渲相邻镜头或转场窗口。连续音乐及跨镜头音效保留在总装时间线。
6. 每期独立目录保存素材、镜头、缓存、修改记录、装配清单和工程备份，不依赖会被其他节目覆盖的共享`.work`。已审版本及素材文件保持可恢复，修订另存版本。

## 局部修改规则

| 用户修改 | 预期重做范围 |
|---|---|
| 一张图、一个人物、一个标签位置 | 使用该素材或参数的镜头；字幕、录音保持复用 |
| 一句旁白 | 所属自然段落的录音/对齐和受其时长影响的镜头；后续装配时间重新计算 |
| 一处字幕 | 对应字幕片段；采用独立字幕轨时无需重做基础图解 |
| 一个新闻片段 | 对应素材与插入点，并复查相邻衔接 |
| 一处转场或镜头时长 | 本镜头以及必要的相邻转场；复用其余镜头 |
| 全片字体、模板、画幅或通用人物变化 | 所有实际引用它们的镜头；影响全片时允许全片重渲 |

共享素材变化必须找出全部引用，不能为减少重渲而漏掉受影响画面。

## 缓存与总装

每个镜头按实际内容、素材文件内容、局部时长、模板/字体版本、画幅、帧率和编码参数计算缓存键。全片中的绝对起点不作为独立镜头失效的原因；跨镜头转场显式记录依赖。相同输入复用已有输出，变更前列出受影响编号与总时长。

合成完整MP4会重新写出完整文件，这与逐帧重建全部动画分开。参数一致且仅拼接时优先复用已编码视频段；涉及全片滤镜、连续转场或混音时可能需要总装编码。具体耗时按实测说明，不承诺任何修改都只花几秒。

Resolve总装保留独立轨道、镜头标记和`.drp`工程备份；每次修订保存新版清单和审阅视频。对齐数据既保留局部时间，也生成当前全片时间，防止改长度后字幕或音效错位。

## 20分钟制作前的验收门槛

- 用少量镜头试跑分段渲染；相同输入第二次运行必须显示0个镜头重渲。
- 移动中间镜头的一处文字后，只重渲该镜头；其余段的文件指纹保持一致。
- 加长中间镜头，后续镜头的视频缓存继续复用，装配后的字幕、旁白和音乐时间正确。
- 修改共享人物素材时，所有引用该图的镜头失效，未引用镜头继续复用。
- 合成后核对时长、帧数、音画同步、片段接缝和文字对齐；原审阅版本仍可打开。

先完成并记录以上实际验收，再扩展到20分钟。16GB机器通过全机重任务锁串行执行；本规范不启用多浏览器并行重渲。

## 审阅方式

每个镜头提供缩略图、稳定编号和当前时间码；用户可按时间码、截图或“这张图”提出修改。修改记录同时保存原版本、问题、实际影响范围及新版本。每次先交受影响片段的可播放预览，再生成需要的整片审阅版。
